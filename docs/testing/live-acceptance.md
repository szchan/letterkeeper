状态：2026-10-15 已获用户明确授权并完成本机已解锁 GNOME Keyring 的凭据往返、跨进程协调与合成条目清理，以及真实 Google OAuth 浏览器登录和 token 保存。随后用户明确允许读取该账户全部邮件，只读 IMAP 的认证、文件夹、分页、ASCII/中文搜索、安全正文抽样与 Flags/UIDVALIDITY 不变检查通过。后续自然到期续期、并发认证、单个服务器草稿写入及 TUI 人工批准通过；首次产品 CLI SMTP 尝试持久化 Failed 并观察到握手超时；用户修复网络并重新在 TUI 人工批准后，CLI 单次发送 Accepted，独立核对 Sent/本人 Inbox 各一个匹配、内容正确及 ServerManaged 无额外 APPEND，测试草稿和邮件保留。没有自动重发。用户在同一 Ghostty 的独立有界按键脚本按 F9 得到 `no_input_received`；只读 `hyprctl binds -j` 确认 Hyprland 默认 submap 有两条 consuming F9 按键/松开绑定，因此环境截获原因已定位。系统绑定未修改，真实客户端 F9 触发仍未验收。锁定或服务失联的真实故障环境仍待独立验收。结果和限制见[钥匙环/OAuth](live-keyring-2026-10-15.md)、[只读 IMAP 记录](live-imap-2026-10-15.md)及[续期/写入记录](live-write-2026-10-15.md)。受控阶段 C 可独立验收，真实服务缺口继续保留在 STATUS。依据 AGENTS.md 的“未经明确授权，不使用真实账户收发测试邮件、删除邮件或修改账户状态”，本次网页观察由用户报告：Gmail 网页两份测试草稿中，成功发送对应的那份已消失，另一份仍在。驱动只记录一次本地草稿和一次 Confirmed Draft APPEND；只读复核当前按合成主题见一个匹配，Message-ID 与该 APPEND 一致。驱动无法重建网页历史两份草稿的身份关系或第二份来源，因此不将其写成刷新/清理故障；没有客户端 DELETE/EXPUNGE。实施代码不自动授权下列真实操作。

## 关卡1：系统凭据库

用户先确认可写入并清理一个专用合成测试条目，以及目标Secret Service环境已解锁。条目标识以letterkeeper-acceptance开头并附随机后缀；仅使用合成密码/token，不读取现有个人条目。验证保存→读取相等（只报告布尔结果）→跨进程协调→删除本次条目→确认不存在。服务锁定/不可用必须拒绝，不生成明文降级文件。只能清理本次创建的条目。

## 关卡2：Gmail授权与读取

执行前明确：专用测试账户id、用户自己的Desktop OAuth client、允许读取的文件夹与邮件范围。默认使用指定合成邮件；用户可以明确授权更广的只读范围，本次已授权全部邮件，但验收仍按抽样而非全量下载执行。client_id可存普通配置，client secret/token在本机隐藏输入或浏览器授权，不发送到聊天/仓库/日志。验证登录、EXAMINE/BODY.PEEK阅读及状态不变，真实续期单列记录。个人OAuth身份注册/公开发行要求按当时官方规则核对；不借用其他客户端身份。授权后的token注销/撤销也是账户状态操作，列入本次清单后才执行。

## 关卡3：明确的写操作

另行给出并授权账户、Drafts/Sent文件夹、唯一测试收件人和单封合成内容。清单为：创建一个标记清楚的测试草稿；通过TUI完整审阅/批准；单次发送；核对SMTP状态及服务商Sent副本；验证ServerManaged不额外APPEND。不批量发送、不删除或EXPUNGE其他邮件。是否清理本次测试草稿/邮件单独列出；没有清理授权就保留并告知位置。

网络断连的写测试优先继续使用本地受控服务，不在真实邮箱上人为重复投递。不确定状态保留，Sent观察不能单独证明投递或授权重发。

## 记录与退出条件

结果记录账户匿名标识、客户端/服务版本、步骤、通过/失败/不确定和剩余限制；不记录邮箱地址、正文、收件人、token、秘密、附件或个人配置。日志主动导出先审查脱敏。没有输入或授权时关卡保持未验收，不能把受控OAuth/vault测试写成真实通过。通过所有关卡也不自动等于全部P0完成，更不授权推送、公开仓库或发行。
