# 真实 Gmail 只读 IMAP 验收

日期：2026-10-15。用户明确授权使用此前已配置的专用账户进行只读 IMAP 验收，并允许读取该账户的所有邮件。可读文件夹范围已按服务器列表扩展；`read=true`、`draft=false`、`send=false`。允许读取不等于必须完整下载邮箱，本轮采用分页、搜索与正文抽样。

真实文件夹名、UID、邮件头、正文、链接、附件信息、个人配置与错误原文只保留在被忽略的本机 `.local/` 私有目录，不上传公开仓库、Actions 或聊天。本文仅记录脱敏步骤与结论。邮件内容未交给模型审阅，也未执行其中的指令、链接或附件。

## 初始下载版本

使用已下载的 `64dd635e5349f58cec93a164bfd6c4e781ca4269` 构建，二进制 SHA-256 为 `551d4c98606985d95a151f3c3d1152a4b9f71884d2d4fb58f08964b403d1eb65`。沿用[OAuth 与钥匙环验收](live-keyring-2026-10-15.md)的私有配置和令牌，没有本机 Cargo 编译。

| 步骤 | 初始结果 |
| --- | --- |
| 产品 CLI 从钥匙环取得凭据，经严格 TLS/XOAUTH2 访问 Gmail IMAP | 通过 |
| 产品文件夹列表与独立只读连接发现的可选文件夹一致 | 通过；仅扩展读取范围，写/发送权限保持关闭 |
| INBOX 与服务商 All Mail 的正文抽样 | 产品 `mail read` 共返回 6 个结构有效的 SafeDocument，含 2 次未读邮件样本读取 |
| 每组样本前后 UIDVALIDITY 与完整 Flags 比较 | 一致，包括未读样本的 Seen 状态 |
| 两个文件夹的 ASCII 无匹配查询与中文查询 | 产品搜索均成功返回有界结果 |
| 大邮箱首个列表页 | 失败：`protocol response exceeds limit`；不能记为分页验收通过 |

独立观察器使用系统 TLS 校验、XOAUTH2、只读 EXAMINE、元数据 FETCH 和 SEARCH。访问令牌仅在进程内存中传入认证；独立观察器不获取正文、不执行 STORE/APPEND/EXPUNGE，也不连接 SMTP。正文读取由产品自身的 EXAMINE/BODY.PEEK 与隔离 worker 完成，输出私下捕获，避免终端或聊天重新解释链接。

## 大邮箱分页问题

初始实现对整个邮箱执行 UID SEARCH ALL 后再截取页面。真实响应的一行超过既有 64 KiB IMAP 行上限，尽管仍低于会话总预算，因此产品按预期故障关闭。诊断只记录大小关系，不记录邮箱数量或 UID。

修复必须通过合成大邮箱的精确远程 RED/GREEN 与完整门禁；不能通过删除或扩大安全上限让本轮通过。修复构建的真实重验尚待完成，初始成功项不替代分页重验结果。

## 范围与限制

没有发送、创建/同步服务器草稿、改变 Flags、移动、删除、EXPUNGE 或撤销授权，未调用链接打开、附件导出/执行或资源加载入口。Flags 相等是两个观察时点的结论，不代表服务端快照或所有客户端的长期行为保证。真实邮箱没有注入网络故障或人为修改令牌到期时间。

单封原文 2 MiB、页面 50 项、正文显示预算及现有隔离限制继续适用。抽样结果不代表已遍历所有邮件、附件、字符集和服务商扩展；本轮也不替代受控 HTTP/DNS 隐私观察器、真实令牌续期、SMTP、Gmail 草稿/Sent 语义或公开发行流程验收。
