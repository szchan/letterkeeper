# ADR 0006：持久化安全发送诊断

日期：2026-10-15。状态：实施中，远程 RED/GREEN 与集成验收尚未完成。沿用 MAIL-07、DATA-02、PRIV-05、MCP-09、UX-01 的发送状态、隐私和错误反馈要求，不改变人工批准或自动重试策略。

## 问题与决定

当前凭据访问、TLS、SMTP 认证和命令拒绝均可能只返回 Failed。不可变发送字节与持久化三态能支持结果查询，但不能还原失败阶段。增加固定枚举的阶段、错误种类及可选 SMTP 数值码，并将其与最终状态在同一 SQLite 事务保存。旧提交缺少诊断时返回未知，不推测历史原因。

保留 Accepted / Failed / Uncertain 的含义、原子认领、单次批准、跨进程锁和无自动重发。Failed 不能单独证明没有进入 DATA；明确最终拒绝与提交后连接不确定继续沿用原语义。Sent 查询仍只是观察证据。

## 接口与存储

- 协议新增 `send_smtp_report`，返回 `SmtpReport { outcome, diagnostic }`；原 `send_smtp` 保留为三态兼容入口。诊断跟踪现有操作的实际阶段，包括全操作超时，不为定位故障额外投递。
- 核心新增 `SendDiagnostic { stage, kind, smtp_code }`，schema 3 使用独立诊断表；`finish_submission_with_diagnostic` 原子提交状态与诊断，原方法仍兼容。`Submission` 与草稿摘要形状保持不变。旧 schema 自动迁移，未来未知 schema 拒绝打开。
- 阶段限定为准备、TLS 配置、凭据、连接、TLS 握手、欢迎语/EHLO、认证、MAIL、RCPT、DATA 命令、提交。提交阶段包括内容传输与等待最终响应，不宣称可区分上游库没有暴露的细节。
- 种类限定为输入无效、连接、超时、拒绝、意外响应、不可用；SMTP 数值码范围为 100–599。协议层不需要凭据阶段及不可用种类，由账户装配层补充。
- Accepted 不带失败诊断。CLI 发送/状态查询与 TUI 使用同一持久化信息；诊断查询失败不能覆盖已有发送结果或触发重发。状态持久化失败继续返回 Uncertain，并明确 `state_recorded=false`。

## 隐私与验证边界

诊断不保存服务器原始响应、错误显示字符串、地址、正文、Message-ID、凭据、令牌或本机配置路径。新增字段不是日志导出或凭据读取接口。读取诊断保持账户与读权限检查；模型不能写入诊断或改变发送授权。

不新增依赖，不实现 SMTP、密码学或不安全降级。协议、核心与应用/TUI 分别使用独立 worktree 和限定文件，先在精确 SHA 上保留远程真实 RED，再实现 GREEN。受控验证覆盖阶段拒绝、证书保护、超时/不确定、原子回滚、迁移/重开、权限、输出脱敏，以及 TUI 到账户 TLS SMTP 的完整路径；无法复现或无法模拟的范围明确记录。不得为模拟 OAuth 放宽 Gmail 的固定端点校验。

完整工作区、PTY、HTTP/DNS 隔离和实际 Codex 门禁仍在 GitHub Actions 执行；本机不运行 Cargo。公开测试、日志和产物只含合成数据。改进诊断不等于已定位任何既有真实失败，也不替代后续真实邮箱验收。
