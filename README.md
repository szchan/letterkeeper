# LetterKeeper

**守护你的信件，也守护你的隐私。**

LetterKeeper 是一个正在规划的开源邮件客户端：支持标准 IMAP/SMTP 和 Gmail 等邮箱的 OAuth 登录，以轻量、精致的 TUI 为优先界面，并通过本地 MCP 让 Codex 等 Agent 搜索、读取、起草和发送邮件。

项目的核心目标是：打开或处理邮件时，正文不会偷偷访问发件者的服务器，不执行邮件中的 JavaScript，也不自动发送已读回执。这些约束同时适用于人阅读邮件、服务端解析邮件和 Agent 接入路径。

## 当前状态

2026-10-12 建立需求与开发指引。当前仓库只有文档，尚未确定技术栈、实现邮件客户端或接入真实邮箱。

下列内容是计划实现的能力，不是现有功能承诺：

- **标准邮件协议**：IMAP 收取与同步，SMTP 发送，TLS 与严格证书验证。
- **OAuth 登录**：优先支持 Gmail 的浏览器授权和 token 续期，不把应用专用密码当成 OAuth 替代品。
- **正文隐私**：默认阻止所有外部资源；禁用脚本、自动导航、链接预览和隐式预取。
- **轻量界面**：TUI 优先，支持中文、主题和键盘操作；运行资源占用需要实测。
- **Agent 接入**：本地 MCP，覆盖搜索、读取、草稿、回复及发送，账户访问与发送策略可控。
- **本地数据保护**：凭据安全存储，日志默认不含邮件内容或秘密，不依赖第三方邮件中转服务。

## 隐私边界

“不加载远程图片”不足以实现我们的目标。外部 CSS、字体、媒体、嵌入页面、SVG 引用、DNS 预取，以及 HTML 转 Markdown 的解析过程，都需要纳入防护和验证。

邮件服务商仍可知道账户连接和服务端状态；用户主动访问链接或放行资源可能暴露访问行为。本地 MCP 可以避免额外的邮件中转平台，但交给云端 Agent 的邮件内容仍会传给模型服务商。项目不能承诺对邮箱服务商或云端模型服务商实现匿名。

完整要求和验收标准见 [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md)。
