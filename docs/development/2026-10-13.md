# 2026-10-13 阶段 B 开发记录

用户要求主代理继续指挥 subagents 进行 TDD，沿用 Git/worktree、分级模型和 docs 记录。本轮不用真实邮箱凭据，以受控 IMAP/SMTP/OAuth 完成代码和协议验收。

## 分工与工作区

- 集成：feat/phase-b / .worktrees/phase-b，基线 main 206c57a；主代理负责 ADR、接口、同步状态、进程锁、CLI/Host、整体验收。
- 协议：feat/b-protocol / .worktrees/b-protocol，GPT-6.1-Sol high；严格 TLS、IMAP/SMTP、资源边界和有状态本机服务。
- 账户：feat/b-accounts / .worktrees/b-accounts，GPT-6.1-Sol high；配置路径/凭据/OAuth，后续只读安全审查与跨进程协调。
- 正文：feat/b-content / .worktrees/b-content，GPT-6.1-Sol medium；回复、线程 ID、附件。
- 适配：feat/b-adapters / .worktrees/b-adapters，复用 medium 子代理；后台 TUI/MCP、取消和并发配额。
- 依赖文档：docs/phase-b-dependencies / .worktrees/b-dependencies，GPT-6-Luna medium；从集成 metadata 生成无本机路径的 registry 清单。

每任务限制可改文件，接口通过消息协调，不跨 worktree 编辑。模块提交经主代理审查后 cherry-pick；子工作区的临时 manifest/lock 不作为最终锁。实际模型名称只描述本轮选择，不代表永久定价。

## TDD 与审查

模块先运行 stub/行为 RED，再实现 GREEN；缺少新 API 造成的编译 RED 在各模块记录中明确注明。主代理新增同步/应用/CLI 的 RED，集成中又补 Sent 范围、凭据预检和不透明 Message-ID 回归。协议测试发现 SDK 后台线程与同步 runtime 桥接不兼容，补真实 TLS RED/GREEN。MCP 并发配额先以 8 个阻塞 Host 正向控制重现第 9 个任务无界，再实现共享配额。最终协议审查补中文搜索和 tagged NO 的真实 TLS RED：原 Unicode 查询为空，SDK 将拒绝当作空结果；改用 UTF-8 同步 literal 和库解析的显式完成检查。

独立审查覆盖授权先于联网、SQLite 兼容迁移、不可变 wire、Sent 范围、凭据锁路径、CA FIFO、附件文件路径和重试语义。修复真实问题，保留 SQLite 同 UID TOCTOU、同步同版本恢复、真实下游及服务商兼容缺口。测试自身的 fixture 身份/目录权限/PTY 控制序列误判如实记录，没有改应用去迎合错误夹具。

执行审批服务曾在新增 adapter worktree 时超时，未执行；按返回指引重试一次成功。后续 medium 子代理因额度中断时保留新配额测试，用户明确恢复额度后原任务接续，没有覆盖已完成工作。
